# Albion Render Fallback for New Items

When Albion Online ships new items, the render CDN (`render.albiononline.com/v1/item/<key>.png`) often serves art by the EN display name — not the UniqueName (`T8_MEAL_SPECIAL_FOOD_DRAKE_EGG`). Crystal weapons and Dragon Leather already have dedicated UID-to-EN converters in the backend; everything else falls through to the raw UniqueName and 404s. This skill adds a generic fallback using `item_names.json` so any new item is covered without per-item hard-coding.

## When to Use

- New Albion update adds items and their icons don't render on the site
- User says "itens novos não aparecem" or mentions Dragon Egg, new artefacts, or similar
- Need to add a new item type to the render pipeline (not crystal weapons or Dragon Leather — those have dedicated paths)
- `render_item` returns 404 for a UID that exists in `item_names.json`

## Prerequisites

- Ziggs backend venv: `backend/venv/Scripts/python` (Windows) or `backend/venv/bin/python` (POSIX)
- `backend/data/item_names.json` generated by `python -m scripts.seed_item_names` (maps UID to EN name)
- `backend/app/api/routes/render.py` is the render proxy endpoint

## Quick Reference

```
_ITEM_NAMES_FILE      = backend/data/item_names.json  (UID to EN name, @lru_cache)
_item_en_names()      -> dict[str, str]                (reads item_names.json once)
_item_en_fallback(uid) -> str | None                 (UID to EN name, strips @0, keeps @N>0)
_item_render_fallback(uid) -> str | None              (excludes crystal/dragon; delegates to _item_en_fallback)

Wired into: render_item, recover_render_miss, _prerender_one
```

## Procedure

1. Confirm the item exists in `item_names.json` with `search_files` on `backend/data/item_names.json` for the UID. If missing, regenerate: `cd backend && venv/Scripts/python -m scripts.seed_item_names`.

2. Verify the CDN does NOT serve by UniqueName but DOES serve by EN name. Use `terminal` with `curl -s -o /dev/null -w "%{http_code}" "https://render.albiononline.com/v1/item/<UID>.png"` vs the EN name from `item_names.json`.

3. Check if the item is a crystal weapon or Dragon Leather — if so, it already has a dedicated converter (`_crystal_en_name`, `_dragon_en_name`). Do NOT add it to the generic fallback; extend the dedicated dict instead (`_CRYSTAL_WEAPON_BASES` or `_DRAGON_LEATHER_BASES`).

4. The generic fallback in `render.py` is already wired. For a new item type that is NOT crystal/dragon, no code change is needed — `_item_render_fallback` resolves it via `item_names.json` automatically. If the fallback functions don't exist yet, add them (see `## Procedure — Adding the Fallback` below).

5. Add the item to `frontend/src/data/albion-items.ts` if it should appear in the comp editor / craft calculator. Use `gen()` for normal items, `art()` for artefacts, `artAll()` only for crystal weapons.

6. Run tests: `cd backend && PYTHONPATH=. venv/Scripts/python -m pytest tests/test_render.py -q`.

## Procedure — Adding the Fallback (if not yet present)

If `render.py` does not yet have the generic fallback, add these three functions after `_dragon_en_name`:

```python
@lru_cache(maxsize=1)
def _item_en_names() -> dict[str, str]:
    try:
        data = json.loads(_ITEM_NAMES_FILE.read_text(encoding="utf-8"))
    except Exception:
        return {}
    return data

def _item_en_fallback(uid: str) -> str | None:
    names = _item_en_names()
    if not names:
        return None
    base, _, ench = uid.rpartition("@")
    if not base:
        base, ench = uid, ""
    en = names.get(base)
    if not en:
        return None
    en = re.sub(r"@0$", "", en)
    if ench and ench != "0":
        en = f"{en}@{ench}"
    return en or None

def _item_render_fallback(uid: str) -> str | None:
    if _crystal_en_name(uid, {}) or _dragon_en_name(uid):
        return None
    return _item_en_fallback(uid)
```

Then wire `fallback=_item_render_fallback(key)` into:
- `render_item` -> `_cached_render(...)` call
- `recover_render_miss` -> `fallback = ... if kind == "item" else None`
- `_prerender_one` -> `_cached_render(...)` call

## Pitfalls

- **Crystal weapons have different names in `item_names.json`.** The file has "Elder's Infinite Crystal" (artefact name) but the CDN expects "Elder's Infinity Blade" (render name). That's why `_item_render_fallback` excludes crystal/dragon — they have dedicated converters with the correct render names.
- **`@0` suffix.** `item_names.json` stores equipment names with `@0` (e.g. `"Adept's Bag@0"`). The CDN does NOT accept `@0` — it must be stripped. `_item_en_fallback` strips `@0` but preserves `@N>0`.
- **`item_names.json` has no `@N` UIDs.** It maps base UIDs only; enchantment variants are derived by appending `@N` to the EN name.
- **Line endings.** `patch` on Windows can produce noisy diffs (CRLF to LF) but `git diff --stat` shows the real change count.
- **lru_cache and module-level constants.** `_ITEM_NAMES_FILE` must be defined before `_item_en_names` is first called. Since it is `@lru_cache(maxsize=1)`, it runs lazily on first invocation — by then all module constants are set.
